FINDINGS AND CONSTRAINTS
- Desktop is Tauri 2 / Rust + TypeScript/WebView2; signaling server is Node.
- Automatic room IDs derive from the current match roster. Optional invite code adds a room namespace without changing match scope. This is not a standalone lobby or an account authorization system. The signaling operator can see room IDs, but client and server diagnostic logs redact private IDs.
- CameraHearing matches roster champion icons against local minimap observations. The Nearby voices visibility filter uses this local evidence; it cannot raycast terrain or guarantee exact handling of all stealth/vision mechanics. The new filter sends no player coordinates.
- SmartScreen depends on file/publisher reputation, not app metadata. There is no trusted signing identity configured here; unsigned releases can warn. See Microsoft's current guidance: https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation
- Keep the updater's canonical filename `lolproxchat.exe`, package name, storage identifier and wire protocol stable.

LIMITS
- Minimap absence is an occlusion hint only; it cannot tell fog of war from brush or invisibility. Nearby mode's explicit visible-only setting still silences hidden enemies; Rift Voices instead applies the voice filter.
- Host rules are authoritative for compatible clients at the signaling layer; a modified client can ignore local audio policy. The first person to enter a code room becomes host, so share room codes only with intended players.
- SmartScreen warning remains possible because the executable is unsigned.
